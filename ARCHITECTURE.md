# Architecture and operating limits

## Data flow

```text
iPhone / browser
  → Next.js UI and authenticated API
  → Google OAuth / Drive API
      ↳ original PDF stays in Google Drive
      ↳ appDataFolder holds this app's JSON records
  → NVIDIA API for requested AI operations
```

The browser gets a short-lived Google access token only when opening Google Picker. The Google client secret, refresh token, and NVIDIA key stay on the server side; the refresh token is held in an encrypted, HTTP-only cookie on each user's device. The OAuth callback requires a verified Google email on `AUTHORIZED_GOOGLE_EMAILS`; every protected request rechecks the allowlist. The verified Google `sub` is the stable tenant identifier. Sessions have an absolute 30-day limit. The app checks the request origin for state-changing calls. Stored PDFs are fetched through an authenticated, bounded HTTP Range proxy so PDF.js can render pages without exposing the source URL or a long-lived credential.

## Storage

Learning JSON records are bounded at 3.5 MB of UTF-8 data on both upload and streamed read. Finalization requests are bounded at 4 MB, under the default [Vercel 4.5 MB payload envelope](https://vercel.com/docs/functions/limitations). New generated quiz items are limited to 10 KB each so a 300-item bank fits with its metadata. A chunk request may contain up to 220 KB, accommodating multilingual source text. No new storage service is used.

The browser splits coalesced PDF.js requests into exact 1 MiB HTTP transfers before delivering the full requested range to PDF.js. Quiz generation performs at most one new five-item batch per HTTP request; a continuation response causes the UI to request the same segment again, reusing signed checkpoints. Only actual model-provider failures trigger fallback, not user quota or Drive reservation errors. Research citations and model provenance follow each saved batch into the final artifact.

The PDF remains at its original Drive file ID. A small reference record, reading position, intermediate chunk map, summary or quiz, quiz attempts, and AI usage reservations are JSON files in **that user's own** Drive `appDataFolder`. Each API call uses the access token from that user's session. The records retain the `margin-v1` app marker. Document records remain schema 1; new artifacts and attempts use schema 2, while old finished artifacts and attempts remain readable. New intermediate maps use schema 3 and are signed with the Google `sub` embedded. Older intermediate maps are not reused. Generated artifacts are immutable; a retry with the same operation ID reuses a saved artifact. An interrupted AI run can reuse that user's signed segment or quiz-batch maps for the same operation ID, Drive MD5, extracted text hash, rule version, style, and assessment plan. An irreparable collection duplicate starts a new operation ID, avoiding reuse of the invalid bank. The `SESSION_SECRET` protects both session data and map signatures; changing it invalidates active sessions and old map reuse, but does not erase saved artifacts.

The app does not migrate or copy PDFs. Drive access is limited to files the user selects through Google Picker and files the app creates. If a PDF is deleted or replaced in Drive, its saved reference may remain, and a changed checksum prevents attaching new AI output to the old content.

## Whole-document processing

PDF.js extracts text from pages 1 through the last page in order. The client identifies major sections from PDF bookmarks, then heading patterns, then explicitly labeled inferred page divisions. It partitions each section into contiguous processing segments (up to 45,000 characters and 80 segments). Every segment must complete; the server validates signed results, their source checksum, ordering, section sequence, and full page coverage before finalizing. Five runtime summary profiles control depth, length, and writing rules. The final whole-PDF summary assembles ordered section summaries without a single truncation-prone final model call. A quiz blueprint allocates 5–300 questions across readable sections using source length and concept-signal heuristics, with at most 10 items per segment and batches of five. The default format target is about 75% multiple response. Medical/dental family rules cover presentation, diagnostic reasoning, investigation, management, contraindications and integrated cases only when supported by the source. Each item includes a source anchor, per-option explanations, and a separate NVIDIA answer audit; a single rejected item can be replaced and the bank audited again. The server scores submitted answer sets by stable artifact option indices; each new attempt shuffles only the displayed positions, so legacy quizzes and saved scores remain valid. The reader renders ten questions at a time to keep large banks usable on phones.

Mistral Large 4 is the primary inference model and receives `reasoning_effort: high` rather than the legacy Nemotron controls. A 45-second primary timeout and temporary provider errors invoke the legacy Nemotron fallback, with a five-minute process-local Mistral circuit. Every provider call reserves a per-user Drive usage record. Finished artifacts record all models that responded. This fallback protects availability but does not establish equal educational quality between models. The model-side reviewer can miss medical errors, so source anchors and review are evidence aids, not a clinical certification.

Optional research mode maps document text to a small, fixed, public medical/dental topic list on the server. Only the topic string is sent to Europe PMC; the PDF, patient details, document title and account identity are never included in the search URL. Up to two abstracts per segment are provided as secondary context for conflict checking. Retrieved citations are saved with the artifact and displayed as limited references, separate from the PDF. An unmatched topic or unavailable research API leaves the operation PDF-grounded. Abstracts alone cannot verify a treatment recommendation or replace a full guideline.

The full set of pages is *visited*, but coverage of meaning is limited by PDF text extraction and AI quality. Scans without a text layer, images, diagrams, unusual fonts, and PDF structure may not be understood. Pages with little extractable text are flagged. There is no OCR. The server checks page-range metadata supplied by the client, but does not independently extract the PDF text a second time. Heading detection can miss or misclassify structure. Source excerpts and model audits are useful checks, not proof of semantic accuracy; educational content still needs human review. A finite quiz may sample only some sections, and the UI reports that gap.

To bound cost and memory, the app accepts downloadable PDFs up to 250 MB and 5,000 pages. It rejects a document that would need more than 80 text chunks or one page whose extracted text exceeds the chunk limit. Chunk maps are kept in Drive to recover from interrupted processing. Google and NVIDIA limits, network errors, and browser memory can still interrupt large documents; the UI shows an error, and no partial final artifact is saved.

Each non-cached model call, including a retry or answer audit, reserves one usage record in the requesting user's Drive before inference. The default is 200 calls per user per UTC day; one in-flight AI operation per user and four total are admitted per Node process. The UI locks an operation before its first asynchronous request, sends an operation ID, supports cancellation, and retries brief process saturation with bounded backoff. The API distinguishes another operation for the same account (409) from process saturation (503). Logs use a hashed account identifier, operation ID, phase, category, and timing without source text or credentials. The shared NVIDIA key remains server-side. These limits are protective but not an atomic global budget across Vercel instances: Drive listing can lag and users can delete their own app data. Check whether this NVIDIA account offers a provider-enforced cap and configure a Vercel Firewall rule for public abuse protection. See [MULTI_USER_ARCHITECTURE.md](MULTI_USER_ARCHITECTURE.md).

## Deployment

This is a Next.js application with no persistent server disk. It can run locally or on a Next.js host with HTTPS. It has no offline PDF cache or service worker; Home Screen installation works, but reading and AI require network access. Google Picker and OAuth need the exact deployed origin. `NEXT_PUBLIC_` Picker values are fixed at build time.
