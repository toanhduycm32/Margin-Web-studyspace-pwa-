# Architecture and operating limits

## Current engineering decision — 28 November 2026

The owner's “Engineering Workflow & AI Execution Redesign” attachment supersedes maximum-depth, one-objective/one-question and mandatory two-item batching assumptions. Protected outcomes are source-supported Vietnamese learning, major-section coverage, correct multiple-response keys, account isolation and safe replacement. Quantity, detail and advanced sophistication are adjustable. Historical reports remain evidence, not active design instructions.

Engineering workflow: inspect the actual path and saved failures → identify the earliest responsible mechanism → compare a direct section baseline → implement the complete PDF-to-Drive path → use recorded/deterministic checks first → run a bounded genuine-document evaluation → inspect educational output separately from software passes. Do not repeat inference to diagnose a deterministic defect. Keep production unchanged until release evidence is sufficient.

Candidate runtime: reuse extracted pages and section boundaries; deterministically allocate a small question group per substantive transport section; combine concept selection and question construction in one compact request; validate IDs, response formats, quotes and scoring in code; review the complete section group against the source; repair only rejected items once; assemble and publish only complete accepted maps. Summary generation uses the existing section transport unit, a soft length guide and one material-content review, without a final whole-document rewrite. Source sections, semantic concepts, physical requests and accepted artifacts are distinct objects.

Initial candidate: at most four questions per section segment, majority multiple-correct, source-appropriate theory/clinical content. This is a deliberately smaller personal-study bank, not exhaustive objective assessment. MiniMax M3.1 Flash with explicit low effort is the first focused candidate, based on existing supported output; this is not yet a qualification claim. No model sweep or automatic fallback. Initial live budget: at most eight new calls and 15 minutes per complete chapter operation (summary and quiz separately), with at most one targeted repair. Expand only for a different unresolved boundary, never an equivalent retry campaign.

Raw responses are private operation-bound checkpoints, not accepted resources. Signed maps bind subject, PDF checksum, rule and operation. A code/prompt/model change invalidates dependent inference identity; a new rule invalidates old unfinished work but preserves finished artifacts. The browser schedules work and can pause when hidden/offline; no autonomous background worker is claimed. Shared quota/admission and Drive publication remain the existing owners.

References are traceability anchors, not semantic proof. A malformed review may be repaired once without redrafting its saved candidate; a substantive rejection allows one summary rewrite. No second mandatory reviewer, model sweep, new service or quiz redesign.

Focused qualification budget: first one mixed control containing the previously observed relation/terminology failures and supported counterparts; then one complete chapter summary through the browser (at most six fresh calls, including conditional format/content repair). Stop on an equivalent semantic failure. An additional control or source is permitted only for a distinct unresolved boundary. Measure button-to-persisted-result time separately from provider latency. Preserve the working four-item quiz/attempt and verify them after replacement. Publishing remains conditional on these content gates and relevant regressions, with physical-device and second-account limitations stated explicitly.

Evidence update: the first repaired browser summary removed the invented mineral/containment errors but compressed a pressure mechanism into an ambiguous coordinated subject. A focused reviewer control still falsely accepted that sentence (12.481s). Stop prompt-only review tuning. For Vietnamese source prose, introduce a deterministic source-custody boundary: every displayed summary line must be a contiguous source span after whitespace, NFC, Markdown decoration and equivalent dash normalization (case and source numbers remain significant). Generation selects/reorganizes source sentences and repairs spacing, without lexical paraphrase. This directly rejects the observed deletion/substitution classes before semantic review. It cannot prove completeness or clinical correctness of the source; the existing one review still checks condition/coverage losses. Foreign-language source still needs translation and cannot use the literal Vietnamese guard; it retains the review boundary and must not be described as having the same deterministic guarantee. One fresh conservative chapter operation and one separate translation-boundary sample are proportionate follow-ups, not an equivalent unconstrained regeneration campaign.

The literal-text experiment failed safely before review: the model copied over 80% of the source and repeated three mismatches on its only rewrite. Private signed Drive checkpoints were retrieved through the already authenticated local server (no browser credential extraction or production endpoint added). They show one real lost character in a clinical term, one repaired source typo, and a Symbol-font glyph/page-boundary mismatch. Merely insisting that a model copy exact text is not a reliable or concise work unit.

Final candidate work unit: the model selects ordered source line ranges under actual source headings, optionally repairing whitespace. The application renders those exact ranges. If the proposed text changes characters, numbers, case or word order, the original range is used instead; no guessed paraphrase is published. Bounds/overlap/order/heading checks are deterministic. Source line indexing retains short numeric lines. One semantic review evaluates the rendered result for source conditions and omissions. A fully verbatim digest is also safe only behind the strict original-span guard; the normal contract uses ranges. Translation/research remains separate. This preserves the two-call happy path and removes dependence on a reviewer catching invented words. Cosmetic source faults may remain; unreadable source is not declared understood.

Final language policy candidate: MiniMax remains the primary for Vietnamese sources. Its two failed translation samples (low and high effort) do not justify using it for foreign-source learning. Model identity is included in checkpoints and actual models in accepted artifacts. No user-facing mode or new credential is added. Foreign summary output budgets scale with requested content rather than granting every short excerpt 10,000 tokens; ordinary Vietnamese selection and quiz budgets are unchanged. Both successful calls were close to the provider deadline, so foreign-language latency remains a material limit, not a whole-book performance claim. ## Data flow

Release checkpoint: the bounded foreign-source quiz request timed out before any accepted output. The broader language policy above remains a candidate, not a released/qualified capability. The owner has been asked whether the first release should explicitly limit new generation to Vietnamese sources or continue holding release for English-source reliability. No silent language restriction is implemented and no production release has occurred while that decision is pending.

```text
iPhone / browser
  → Next.js UI and authenticated API
  → Google OAuth / Drive API
      ↳ original PDF stays in Google Drive
      ↳ appDataFolder holds this app's JSON records
  → NVIDIA API for requested AI operations
```

The browser gets a short-lived Google access token only when opening Google Picker. The Google client secret, refresh token, and NVIDIA key stay on the server side; the refresh token is held in an encrypted, HTTP-only cookie on each user's device. The OAuth callback requires a verified Google email on `AUTHORIZED_GOOGLE_EMAILS`; every protected request rechecks the allowlist. The verified Google `sub` is the stable tenant identifier. Sessions have an absolute 30-day limit. The app checks the request origin for state-changing calls. Stored PDFs are fetched through an authenticated, bounded HTTP Range proxy so PDF.js can render pages without exposing the source URL or a long-lived credential.

## Storage

Learning JSON records remain bounded at 3.5 MB UTF-8, finalization requests at 4 MB and new questions at 10 KB. Current allocation is at most four questions per transport segment (80 segments); legacy finished larger banks remain readable. A chunk request accepts up to 220 KB. No new storage service is used.

Each HTTP request completes at most one new model response, saves a private signed checkpoint, then yields at the next inference boundary. The next request replays exactly matching responses before continuing. A completed model response is never an accepted resource by itself. A provider or quota error during review preserves the draft instead of triggering another draft. One structural retry and one selective semantic repair bound the section quiz path; summary drafting has at most one rewrite. Exhausted content failure stops the operation and preserves the current artifact. No automatic model fallback is enabled.

The compact quiz contract puts semantic correctness beside each option. Application code derives stable zero-based keys and select-N counts, attaches source excerpts, question IDs, page ranges and storage metadata. Evidence IDs can name one line, a bounded range, or a list; every referenced endpoint must resolve to actual indexed source. The retained excerpt is an anchor, not independent proof of every claim. A section-level reviewer receives the full source and all options/explanations. It checks medical conditions and answer validity; simple structural validation does not establish correctness.

The PDF remains at its original Drive file ID. A small reference record, reading position, intermediate chunk map, summary or quiz, quiz attempts, and AI usage reservations are JSON files in **that user's own** Drive `appDataFolder`. Each API call uses the access token from that user's session. The records retain the `margin-v1` app marker. Document records remain schema 1; new artifacts and attempts use schema 2, while old finished artifacts and attempts remain readable. New intermediate maps use schema 3 and are signed with the Google `sub` embedded. Older intermediate maps are not reused. Generated artifacts are immutable; a retry with the same operation ID reuses a saved artifact. An interrupted AI run can reuse that user's signed segment or quiz-batch maps for the same operation ID, Drive MD5, extracted text hash, rule version, style, and assessment plan. An incomplete or invalid collection is refused; accepted resources remain available. The `SESSION_SECRET` protects both session data and map signatures; changing it invalidates active sessions and old map reuse, but does not erase saved artifacts.

The app does not migrate or copy PDFs. Drive access is limited to files the user selects through Google Picker and files the app creates. If a PDF is deleted or replaced in Drive, its saved reference may remain, and a changed checksum prevents attaching new AI output to the old content.

## Whole-document processing

PDF.js visits pages 1 through the end in source order. Bookmarks, headings and explicitly labeled inferred divisions identify major sections. Each section is partitioned into contiguous transport units normally up to 18,000 characters, retaining dense pages up to 45,000. The reader reuses this prepared representation for summary/quiz while the account, PDF object, checksum and rule stay identical; it is memory-only and is not shared across accounts.

Summary: one draft and one material-content review per transport segment; soft length guidance rather than a word-count rejection; hard storage, language, heading and actual repetition checks remain. Validated sections assemble deterministically in source order without an extra full-book rewrite. Clinical conditions and important source relations cannot be removed merely to shorten text.

Quiz: deterministic allocation gives each substantive segment two to four questions according to source size. The generator selects concepts and writes questions together. There is no separate model planning call and no one-objective/one-question requirement. The retired planning endpoint returns 410 to old tabs. Most slots are multiple-correct, with single-best reserved within groups of three or four. Families and cognitive demand describe the actual question. A small personal-study bank is allowed to sample concepts; every major substantive section must contribute, and the UI must not claim exhaustive objective coverage. All pages/segments still participate in signed finalization. Source front matter, references and self-assessment are excluded from teaching, while unreadable pages remain disclosed.

The section group is the generation and review unit; HTTP requests remain smaller replayable steps. One group review derives a key for every question without receiving the draft index array, and checks important conditions, source support, useful diversity and appropriate theory/clinical application. Explanations remain visible for claim checking, so it is not a blinded audit. Application code rejects missing per-item decisions and key disagreements. Only rejected items are replaced once, and the resulting collection is checked again. There is no random sampling exemption for high-consequence clinical content. Same-model review is fallible and is not expert certification.

Current model selection is explicit through NVIDIA_MODEL; MiniMax M3.1 Flash with low effort is the focused redesign candidate. Model-specific controls are in nvidia.ts. A provider call has 260 seconds, an AI route 280 seconds and the function declaration 300 seconds. Streaming is not used in the normal runtime and would not extend the host deadline. Logs contain model, outcome, elapsed time and provider-reported token counts, never PDF text or credentials. Every fresh provider call reserves the existing per-user quota; checkpoint replay does not.

The default study path uses PDF grounding to avoid unconditional external retrieval. Existing optional server evidence support and historical cited artifacts remain available. Outside notes/abstracts must be labeled separately; PDF grounding must not be described as current clinical guidance. OCR, images and independent expert validation are outside this candidate's demonstrated capability.

The full set of pages is *visited*, but coverage of meaning is limited by PDF text extraction and AI quality. Scans without a text layer, images, diagrams, unusual fonts, and PDF structure may not be understood. Pages with little extractable text are flagged. There is no OCR. The server checks page-range metadata supplied by the client, but does not independently extract the PDF text a second time. Heading detection can miss or misclassify structure. Source excerpts and model audits are useful checks, not proof of semantic accuracy; educational content still needs human review. A finite quiz may sample only some sections, and the UI reports that gap.

To bound cost and memory, the app accepts downloadable PDFs up to 250 MB and 5,000 pages. It rejects a document that would need more than 80 text chunks or one page whose extracted text exceeds the chunk limit. Chunk maps are kept in Drive to recover from interrupted processing. Google and NVIDIA limits, network errors, and browser memory can still interrupt large documents; the UI shows an error, and no partial final artifact is saved.

Each non-cached model call, including a retry or answer audit, reserves one usage record in the requesting user's Drive before inference. The default is 200 calls per user per UTC day; one in-flight AI operation per user and four total are admitted per Node process. The UI locks an operation before its first asynchronous request, sends an operation ID, supports cancellation, and retries brief process saturation with bounded backoff. The API distinguishes another operation for the same account (409) from process saturation (503). Logs use a hashed account identifier, operation ID, phase, category, and timing without source text or credentials. The shared NVIDIA key remains server-side. These limits are protective but not an atomic global budget across Vercel instances: Drive listing can lag and users can delete their own app data. Check whether this NVIDIA account offers a provider-enforced cap and configure a Vercel Firewall rule for public abuse protection. See [MULTI_USER_ARCHITECTURE.md](MULTI_USER_ARCHITECTURE.md).

## Current-resource replacement and recovery

`/api/ai/begin` creates an immutable operation in the authenticated user's Drive. Its Drive-issued creation timestamp orders operations; the operation binds Google subject, PDF ID, MD5 and resource type. Plans and maps bind the same operation, subject, source version and rule version. The browser's resume key also includes the signed-in account.

An accepted immutable artifact is written before cleanup. Reads choose the highest operation order independently for summary and quiz. Legacy artifacts use Drive creation time with deterministic ID tie-breaking; reading existing history never deletes it. Explicit regeneration retires only lower-order artifacts of the same PDF and type, and only attempts associated with the exact old quiz ID. A delayed lower-order result is rejected and cannot remove the winner. Idempotent retry reuses the accepted artifact and retries deferred cleanup. A stale quiz submission is checked before and after writing; it cannot be attached to a new bank.

Drive listing is eventually consistent; this is **not atomic publication or a distributed lock**. A successful write followed by a lost acknowledgement can be discovered after reload or idempotent retry. Once final save starts, the UI disables cancellation and requests confirmation from Drive; it does not promise rollback of an already accepted write. Cleanup failure is deferred rather than reported as failure to create the already persisted resource. Concurrent submission/cleanup and delayed listings can leave redundant hidden records until reconciliation; no unrelated data is removed. Original PDFs, credentials and reading progress are outside cleanup scope.

## Deployment model

This is a Next.js application with no persistent server disk. It can run locally or on a Next.js host with HTTPS. It has no offline PDF cache or service worker; Home Screen installation works, but reading and AI require network access. Google Picker and OAuth need the exact deployed origin. `NEXT_PUBLIC_` Picker values are fixed at build time.
