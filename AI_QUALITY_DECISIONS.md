# AI quality decisions and evaluation — 2026-11-25

## Evidence and choices

- The [NVIDIA hosted API reference](https://build.nvidia.com/nvidia/nemotron-3.5-lightning-30b-a3b/apireference) documents this app's Chat Completions endpoint, model ID, non-streaming mode, `reasoning_budget`, and `chat_template_kwargs.enable_thinking`. A live uncached request with the local configured key returned HTTP 200, the expected model ID, final content, and separate reasoning content. This does not verify the production key or long-PDF capacity.
- [Texas A&M's summarizing guide](https://writingcenter.tamu.edu/guides/resources/summarizing.html) emphasizes retaining a source's main ideas and structure. [HIBRIDS](https://aclanthology.org/2022.acl-long.58/) shows why hierarchy matters in long-document summarization. Margin uses PDF bookmarks first, then heading patterns, then labeled inferred divisions. A processing segment is never presented as an original heading. Four versioned runtime profiles control purpose, depth, length, terminology, formulas, examples, limits, and validation. Adaptive targets use source length and profile; no final model call can silently truncate all sections.
- [Waterloo](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/designing-multiple-choice-questions), [UC Davis](https://cee.ucdavis.edu/selected-response-exam-items), and [UNSW](https://www.teaching.unsw.edu.au/assessing-multiple-choice-questions) motivate clear stems, plausible distractors, complete answer keys, and useful feedback. [Cornell's Bloom guide](https://teaching.cornell.edu/resource/blooms-taxonomy) motivates separate cognitive-demand labels. Margin keeps response format, question family, cognitive demand, and estimated difficulty separate. The default format mix is a product choice, not a research-derived universal proportion.
- Exact-set scoring has a simple, deterministic contract for multiple-response items and avoids awarding credit for selecting every option. It can underrepresent partial knowledge; partial credit remains a future option only with a validated scoring rule. The model does not grade learner answers.

## Controlled evaluation

- A three-page synthetic source with known claims about gradient descent, learning rate, convexity, and generalization was run through the real NVIDIA endpoint. One live run produced an approximately 190-word summary covering all three subjects and one each of select-all, select-N, and single-best. Human review found a true but irrelevant distractor in the single-best item, so the generation rules were tightened and a separate answer audit was added.
- A later run exposed missing answer fields and a wrong `selection_count`. Runtime schema validation rejected those results. The rules now send the exact validation failure back for bounded regeneration and repeat a required-field checklist after the source text.
- The final live run passed in about 71 seconds, with a summary and three structurally valid, audited items. Human review found the answer sets defensible on this sample. The wording still included some extrapolation, such as vector notation where the supplied source gave only a scalar update, and one claim framed differentiability as necessary for a convexity result. This is why the app reports source evidence and extraction gaps but does not claim verified educational correctness.
- Automated checks cover section coverage and heading fallbacks, profile allocation, multiple-response schema and scoring, cache and tenant boundaries, admission outcomes, regeneration after an audit rejection, old resource compatibility, and the build. `pnpm typecheck`, `pnpm test` (43 passed; optional live test skipped), and `pnpm build` passed after the change.

## Limits still requiring real-world checks

- The production 429 observed in Vercel logs lacked an account identifier or admission reason. The code did use one message for both account activity and process saturation, and the UI had an asynchronous duplicate-tap window. Those defects are fixed and privacy-preserving diagnostics now distinguish future causes; the exact historical account failure cannot be proven from the old logs.
- The two authorized accounts have not yet performed simultaneous authenticated PDF and AI runs in independent sessions. No physical iPhone test was observed.
- Extraction visits every page, but scanned/visual content and misdetected headings can still reduce semantic coverage. A finite quiz may not assess every section. The model audit is another fallible model judgment, not an independent proof against subtle scientific mistakes.
- Process admission and Drive-backed quota remain best effort across serverless instances. A provider-enforced spending cap is the strongest available account-level protection when offered.

## Medical and dental learning upgrade — 2026-11-27

- The [NVIDIA Mistral Large 4 API reference](https://build.nvidia.com/mistralai/mistral-large-4-1t-a52b/apireference) specifies the hosted model ID and `reasoning_effort: high`; the previous Nemotron reasoning controls do not apply to that model. An initial short live request using the existing private key returned HTTP 200, final content, and separate reasoning. A more demanding live three-page generation exceeded a 110-second model timeout. A later 45-second primary deadline reached the Nemotron fallback, which returned a source summary and structured questions but exposed an overlong reviewer trace. The reviewer is now run without Nemotron thinking, and a direct live JSON reviewer probe returned a compact valid result. After tightening the output schema, a live three-page summary and mixed-format quiz completed in about 178 seconds through the fallback. A separate live dental/medical fixture completed in about 91 seconds through the fallback and produced defensible source-conditional answer keys. These small tests do not prove Mistral throughput or general clinical correctness.
- The [NBME item-writing resource](https://www.nbme.org/institutions/nbme-item-writing-guide/) and [INBDE item-development guide](https://jcnde.ada.org/-/media/project/ada-organization/ada/jcnde/files/inbde_item_development_guide.pdf) informed the separation of learning objective, stem conditions, clinical stimulus, response type and answer review. The [INBDE preparation page](https://jcnde.ada.org/inbde/inbde-prepare) restricts reproduction of sample items; the runtime instructions require original items rather than copied exam-bank wording. Margin's 75% multiple-response target is a product choice and should not be described as the actual INBDE distribution.
- A medical/dental source can be classified by several terminology signals. Section prompts explicitly preserve population, severity, thresholds, time course, contraindications, uncertainty and unsupported gaps. Clinical families are applied only where source material supports them. The model-side audit checks zero-based answer IDs, every option's truth under the same stem, and clinical action conditions. A single item identified by the reviewer may be repaired and the whole batch audited again. Model review is still fallible; a contiguous quote alone does not prove the answer.
- Five summary profiles now have distinct goals, lengths and source conditions. The whole-PDF final result still assembles all ordered section digests; it does not run a global model synthesis that could silently truncate a textbook. Suggested quiz count uses readable text, concept signals and section coverage, with explicit choices up to 150 and at most 10 items per segment. This is capacity planning, not a guarantee of 300 unique defensible questions. Failed batches remain retryable from signed Drive maps, and a partial bank is never saved as complete.
- The [ADA dental antibiotic guideline](https://www.ada.org/resources/research/science/evidence-based-dental-research/antibiotics-for-dental-pain-and-swelling) and [WHO ferritin guideline](https://www.who.int/publications-detail-redirect/9789240000124) illustrate why clinical population, setting, inflammation and exceptions matter. These references are development calibration, not hidden patient-care advice in the model prompt. Runtime research mode uses the [Europe PMC REST API](https://dev.europepmc.org/RestfulWebService) with fixed broad topics only. Retrieved abstracts are secondary conflict signals; they cannot establish a treatment recommendation by themselves. The UI displays actual citations or states that none were retrieved. Retrieval failure must never be represented as a completed evidence check.
- Answer positions shuffle on each fresh attempt using browser cryptographic randomness. Saved option indices remain stable IDs within each artifact, so the API's exact-set scoring, old quizzes and past attempts remain compatible. A user who selects every option gains no exact-set advantage.
